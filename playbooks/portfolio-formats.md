# Portfolio formats: content once, shown anywhere

Designers keep portfolios in many places: their own website, a PDF, a Figma or Canva file, Notion, Behance, a slide deck, or nowhere yet. This kit does not edit a portfolio. It writes the content and the visual briefs, then adapts them to where the portfolio lives. The person makes the change.

## Start with one question

"Where does your portfolio live, and who edits it?" Then pick an adapter.

## The eight frames

Every case study, in any format, is these eight frames in this order. See `templates/case-study.example.md`.

1. Outcome strip: three facts in big type
2. Problem: one sentence
3. Role: what you personally did
4. Constraint: what made it hard
5. Decision: what you chose, and the option you rejected
6. Process artifact: one visual that shows how you think
7. Result: with evidence grades, or an honest "no result yet"
8. Reflection: what you would change

## Adapters

| Lives in | You get |
|---|---|
| Own website or CMS | Markdown per frame, an alt text for each image, and a prompt for the person's coding agent (see `templates/portfolio-brief.example.md`) |
| Figma, FigJam, Canva, Keynote, Google Slides | A frame-by-frame spec: frame name, headline, body with a word cap, visual brief, and one speaker line. Eight frames, 16:9 |
| PDF | The same frames as pages, with page size, a text cap per page, a file size target under 10 MB, and the links that must be live |
| Notion, Read.cv, Behance, LinkedIn Featured | Markdown blocks in the order the platform shows them |
| Nowhere yet | A one-page proof sheet for one case study: the strip, problem, decision, result. Enough to start applying. Build the rest later |

## Visual briefs

For each frame, say what the visual should show and what to annotate, not just "add a screenshot". Examples:

- Outcome strip: a number in 72pt type with one line of context beneath.
- Decision: the chosen design beside the rejected one, with one line on why.
- Process artifact: the messy middle (a map, a sketch, a test grid), cropped and captioned.
- Result: a before and after at the same scale.

Every image gets a caption that says what to notice.

## Visual checklist

Check any screenshot or page the person shares:

- Does one thing win attention in the first second?
- Is the outcome visible before the prose?
- Are images annotated, or are they decoration?
- Is there real content, not lorem ipsum or empty states?
- Does text hold contrast and size on a phone?
- Is one process artifact shown, not only polished screens?
- Does the order match the eight frames?

## Updating without a website

The person pastes a screenshot or export of the current page. The assistant runs the signal check and the visual checklist and returns changes in the person's format, frame by frame. For a PDF, a new page list. For a Figma file, a list of layers to edit. The person applies them.

## Do not

- Claim to have edited the portfolio.
- Invent visuals, data or outcomes. A visual brief describes what to show from real material.
- Show NDA-protected work. Ask first.
